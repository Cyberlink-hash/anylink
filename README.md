# AnyLink · 定制增强版

本仓库基于 [bjdgyc/anylink](https://github.com/bjdgyc/anylink) 二次开发，主要围绕 LDAP / LLDAP 用户管理、OTP 开通、网络访问控制和 DNS 配置进行优化。

感谢原作者 **bjdgyc** 及所有上游贡献者对 AnyLink 的开发与维护，为这些改进提供了基础。本仓库是独立维护的衍生版本，VPN 协议实现和基础能力来自上游；以下仅介绍本仓库新增或改进的内容。

许可证沿用 [AGPL-3.0](LICENSE)。原项目介绍及基础部署文档请参阅[上游仓库](https://github.com/bjdgyc/anylink)。

## 网络策略与访问控制

新增可复用的网络策略，在同一用户组内实现不同用户的访问权限管理，无需为了少量权限差异拆分大量用户组。

- **用户选择**：支持搜索并多选用户名，无需手动填写用户名列表。
- **连接来源条件**：支持按 VPN 连接来源 IP 或 CIDR 网段匹配。来源地址是服务端看到的客户端连接地址，通常为公网出口 IP。
- **目标访问控制**：支持按目标 IPv4 地址或网段、协议、端口设置允许或拒绝规则。
- **跨组复用**：同一网络策略可被多个用户组引用，每个组可调整策略关联顺序。
- **顺序匹配**：先匹配用户名和来源条件，再按顺序匹配目标访问规则；未命中时继续匹配后续策略，最终回到组原有的权限控制规则。
- **路由边界**：网络策略不能扩大最终下发的路由范围，排除路由优先拒绝。用户连接策略选择自定义路由时覆盖组路由，选择继承时使用组路由，不将两者取并集。
- **DNS 与分片处理**：启用网络策略时，DNS 53 端口的原有放行例外也受路由边界约束，并拒绝 IPv4 分片，避免分片绕过端口检查。
- **配置保护**：被用户组引用的网络策略不能直接删除；保留旧版条件引用的兼容处理。

例如，同组的张三可以不限连接来源访问管理台；李四则先匹配固定来源允许规则，再由拒绝规则兜底，实现仅从指定出口 IP 连接时才能访问管理台。两人的访问范围均不能超出最终路由权限。

网络策略需关联到实际登录的用户组才会生效，多组登录场景应分别关联。来源条件不满足表示跳过该策略，并不自动拒绝访问；限制访问时应配置明确的拒绝规则。配置修改后重连生效，当前目标访问规则针对 IPv4。

## 用户连接策略与配置预览

“用户信息 → 用户连接策略”支持按用户和登录用户组设置连接方式。新策略默认所有模块继承，必须明确选择指定组或“所有用户组”；路由、DNS、本地网络和动态拆分域名可以分别自定义。自定义路由必须明确填写网段或 `all`，不再用空白隐式表示全隧道；自定义 DNS 会完整覆盖 DNS 模块，自定义动态拆分域名且两项为空表示清除组设置。

匹配顺序：启用的指定组策略 → 启用的所有组策略 → 用户组默认配置。只选一份用户策略，其继承项直接使用登录组，不叠加另一份用户策略。停用或删除指定组策略会回退到所有组策略（若存在）；若希望指定组完全使用组默认值，可以保留一份启用且所有模块继承的指定组策略。同一用户每个范围只保存一份策略，策略不会增加用户的组成员资格。

例如张三在办公组使用分流，在运维组使用全隧道：为张三的运维组添加策略，仅将路由改为自定义 `all`，DNS 和其他模块保持继承。办公组继续使用自身配置，除非另外存在适用于所有组的策略。

预览支持“用户＋登录用户组”，也支持编辑中的未保存配置，显示合并后的路由、DNS、各模块来源及组关联网络访问策略。预览不会保存数据，不等同于登录资格检查或目标地址/端口的 ACL 判定；客户端出口排除路由等会话相关参数在连接时生成。保存前显示范围和模块变更摘要；修改在重新建立隧道后生效，不主动断开在线连接。

升级时旧策略仍为“所有用户组 / 旧版兼容模式”，保留原路由覆盖及 DNS 特殊继承行为。旧策略可以继续编辑，转换新版后需核对 DNS 预览，再选择范围和继承模块。启动时增加策略范围和模块字段，将用户名唯一索引迁移为用户名＋用户组联合唯一索引；升级前保留数据库备份。创建同一用户的多组策略后不能直接用旧版程序读取该数据库，回退应使用配套备份。

## LDAP / LLDAP 兼容与用户同步

### LLDAP 用户组兼容

- 在 LDAP 不支持现有 memberOf 查询方式时，回退检查 groupOfUniqueNames / uniqueMember 或 groupOfNames / member，提高 LLDAP 用户组认证兼容性。
- 外部认证成功后维护用户记录与组归属，并记录认证类型；LDAP 用户必须先由管理员同步开通，不再通过首次登录自动建档。
- 定时检查已有 LDAP 用户是否仍符合组成员要求，不再符合时停用。

### 手动同步 LDAP 用户

- 管理员可在用户列表主动触发同步，按已有的 LDAP 用户组导入用户，无需等待用户首次登录 VPN。
- 登录、LDAP 同步、后台新增／修改和 Excel 导入统一使用小写用户名；保存时忽略大小写检查重复，保留原账户的 OTP 和停用状态。
- SQLite 增加数据库层的用户名小写校验，结合原有唯一索引，防止并发重复创建账户。升级时自动将无重名的旧用户名转为小写并去掉首尾空格，同时更新用户策略、IP 绑定及网络策略引用，保留账户 ID、OTP 和状态；历史日志保留原记录。若存在大小写重名、空用户名或关联策略冲突则停止启动并回滚迁移，不自动合并或删除账户。其他数据库仍使用应用层规范化与原有唯一约束。
- 同步支持新增用户、更新资料和补充组归属，不因一次同步结果删除用户或移除组。
- 同步只读取 LDAP，不修改 LDAP 中的用户和组。
- 多个用户组共用同一套 LDAP、相同用户名代表同一人时，复用本地用户记录并补充组归属。
- 同名非 LDAP 用户会跳过，避免覆盖其他认证类型的账户。

### 姓名与邮箱同步

- 从 LDAP 获取 displayName 和 mail，更新 AnyLink 中的姓名与邮箱。
- LDAP 非空资料覆盖本地对应字段，空邮箱不清空已有邮箱。
- displayName 为空时，使用用户名作为显示名称。

### 新增用户 OTP 与邮件

- 手动同步新增的 LDAP 用户默认开启 OTP，并尝试向用户邮箱发送一次开通邮件。
- 已有用户保留原 OTP 开关、密钥和停用状态，不因同步重置或自动启用。
- 邮件发送失败不回滚用户创建，同步结果单独提示失败；再次同步不重复发信，可在用户编辑页补发。
- 沿用现有“独立 OTP 认证”设置，邮件发送使用已配置的 SMTP 服务。

## 用户设备管理与可选设备绑定

用户列表新增“设备管理”，支持设备备注、批准新增、替换旧设备、拒绝申请、撤销授权、删除非授权记录和管理操作记录。每个用户单独开启，默认关闭，升级不会自动限制现有 Cisco 或 OpenConnect 用户。

“用户信息 → 设备审批”集中展示所有用户的设备，默认筛选待审批，支持按用户名和状态查询、逐台批准新增、替换旧设备或拒绝，也可打开该用户的完整设备管理。菜单显示待审批数量，操作后刷新并每分钟更新；用户列表支持按“设备绑定：已开启 / 未开启”筛选，未开启包含新建及同步新增用户。审批与用户设备管理共用记录，批准设备不会自动开启绑定。申请时间从首次进入待审批时记录，旧记录缺失时显示“未记录”。

首次开启建议：进入设备管理 → 导入近期已连接设备 → 与用户核实设备并填写备注 → 勾选可信设备 → “批准所选设备并开启绑定”。也可以让用户先正常登录一次收集候选。导入仅使用最近30天内最近500条连接成功日志，历史记录不会自动获批。开启时未批准设备的在线和休眠会话失效，已批准设备继续在线。

开启后，新设备通过完整密码及适用的 OTP 认证才会生成待审批申请，获批前不会建立 VPN 会话；管理员批准后用户重新连接即可。同一用户可以批准多台设备，换机可用“替换旧设备”一次完成新机批准和旧机撤销。撤销会关闭相关会话，旧会话不能通过重连恢复。拒绝或撤销不会因再次登录自动恢复授权；删除记录后可以重新申请，但不会自动批准。

绑定保存客户端标识的 SHA-256 摘要，首次登记优先使用 `unique-id-global`，缺失时使用 `unique-id`，随后固定匹配该字段。IP、系统版本和客户端版本变化不作为换机依据。设备标识由客户端上报，可以仿冒，不等同于设备证书；重装客户端等造成标识变化需要重新审批。不提供标识的 OpenConnect 用户可保持关闭绑定，开启绑定的账户不会因使用 OpenConnect 而绕过限制。

每用户最多保存50条设备记录；开启绑定时，最近一小时已新增5条登录设备记录后暂停新增申请。设备记录独立于用户日志保留，管理页展示最近50条管理操作。升级需同时部署前后端，启动时自动创建相关数据库表；首次上线建议先在少量用户上验证实际客户端的审批和重连体验。

## 用户管理体验与批量操作

- 修复搜索输入后按回车不生效的问题。
- 修复翻页时丢失搜索条件的问题。
- 用户管理、网络策略用户搜索及在线用户的用户名搜索忽略大小写。
- 增加用户组、认证类型、启用状态和 OTP 状态筛选。
- 支持对当前页勾选的用户批量执行五类操作：启用、停用、开启 OTP、关闭 OTP、删除。
- 批量停用时同时断开用户的在线连接。
- 在外部认证、会话创建及隧道重连时补充本地用户状态检查，使停用状态得到执行。

## 用户组复制

- 支持复制现有用户组，减少重复配置工作。
- 自动生成不重复的组名，方便基于现有组建立相似配置。

## Split DNS 配置优化

- 为用户组和用户策略增加内网域名、关闭全局 DNS 的配置与校验。
- 规范域名输入，减少格式差异导致的配置问题。
- 修正 Split DNS 配置下发，以及用户策略覆盖过程中的相关行为。

## DTLS 与登录错误提示

- 服务端关闭 DTLS 时，不再向客户端下发 DTLS 连接头。
- 对返回客户端的认证错误进行脱敏，避免直接暴露底层 LDAP 连接信息。此项针对客户端提示，不代表所有服务端日志均已脱敏。

## 仓库清理

- 忽略 macOS 自动生成的 .DS_Store 文件，并移除当前版本中已跟踪的相关文件。
- 将本地运维笔记加入忽略规则，避免作为项目文件提交。

## 从源码构建

在仓库目录执行 `bash build_web.sh && bash build.sh`。需要 Docker Desktop 或启用了 BuildKit 的 Docker Engine，构建默认使用本机架构。

- Node 24、Go 1.26 和 Alpine 3.23 官方基础镜像已固定多架构 SHA-256 摘要；更新时应重新核实摘要并验证构建。
- 前端在容器内使用冻结的 Yarn 锁文件安装依赖，禁止安装脚本，以普通用户离线编译，不挂载宿主机源码或复用本机 `node_modules`。Vue CLI 4 / webpack 4 暂时需要 OpenSSL legacy provider，仅在离线编译步骤启用；IPC 依赖固定到支持 Node 24 的 `9.2.10`。
- 后端使用官方 Go 代理和校验数据库，下载前后校验 `go.mod` / `go.sum`，随后离线、只读模块编译。不会在发布构建中执行 `go mod tidy`，也不再使用 UPX 压缩或在宿主机执行产物。
- 构建失败立即退出；成功后按本次镜像 ID 导出，不回退到旧镜像或上游镜像。本地镜像命名为 `local/anylink:<版本>`。普通构建不推送镜像，原有 `bash build_docker.sh cntest` 仍是显式发布测试镜像的命令。
- 发布目录为 `anylink-deploy`，压缩包为 `anylink-deploy-<版本>.tar.gz`。发布包只带 `conf/server-sample.toml` 和客户端 profile 模板，不含实际 `server.toml`、证书私钥或数据库。首次部署需复制模板为 `server.toml`，设置独立的管理员密码、JWT 密钥、网络参数，并提供自己的 TLS 证书；升级现有服务时保留部署端配置和数据库。
- 请在源码构建目录运行脚本，勿把正在运行的服务配置放在生成目录中；成功构建会替换旧生成目录。官方源不可达时构建会失败，不自动切换第三方源或关闭校验。

构建流程回归测试：`python3 tests/build_scripts_test.py`。镜像摘要和依赖校验用于固定构建输入，不代表所有依赖已通过漏洞或恶意代码审计。
